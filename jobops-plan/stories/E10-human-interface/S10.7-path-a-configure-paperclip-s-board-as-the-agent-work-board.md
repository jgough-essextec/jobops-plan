## User story

As Doc, I want Paperclip's own Board view set up as a parallel board of the agents' work so that I can watch and nudge what each agent is doing without leaving Paperclip.

## Context

Columns are Paperclip issue statuses (backlog, todo, in_progress, in_review, blocked, done, cancelled). Saved board per project (Discovery, Applications, Inbox) and a 'Needs Doc' board filtered by label. Issue labels (stage:*, tier:*, agent:*) from S04.6 make cards readable. Status changes Doc makes on the board are mirrored: a webhook/poller maps meaningful moves to commands (e.g., blocked→todo = retry; any→cancelled on a job issue = Skip via the S10.3 command service), so the ledger stays the source of truth.

## Acceptance criteria

- [ ] Saved boards exist per project and are recreated by company-as-code apply where Paperclip supports it, or documented as one-time setup where it does not
- [ ] Doc's moves that have a pipeline meaning reach the ledger through the S10.3 command service; others only change the issue
