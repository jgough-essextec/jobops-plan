## User story

As the builder, I want the real Paperclip REST endpoints and hermes_local adapter behavior captured so that company-as-code, the fake Hermes harness and the Manager's API calls are built against facts.

## Context

Paperclip: companies, org chart, issues, comments, approvals, budgets, heartbeats, audit, REST API (and an MCP server package). hermes_local runs `hermes chat -q` per run with promptTemplate variables (agentId, companyId, runId, taskId, taskTitle, taskBody, projectName, paperclipApiUrl, commentId, wakeReason), `persistSession` via `--resume`, `toolsets`, `timeoutSec`, `hermesCommand`, `env`. Docs and adapter README differ on some keys — resolve here.

## Acceptance criteria

- [ ] Captured request/response JSON for: create company, create agent, create/update/comment issue, assign, checkout, approval request/resolve, budget read, cost report
- [ ] Verified that `hermesCommand` can point to an arbitrary executable and that Paperclip records its output as a run (proves ADR-7)
- [ ] Resolved key discrepancies (e.g. `toolsets` vs `enabledToolsets`, default `timeoutSec`) documented with versions
