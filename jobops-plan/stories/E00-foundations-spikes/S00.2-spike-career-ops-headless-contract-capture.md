## User story

As the builder, I want to know exactly how career-ops can be driven without an interactive CLI session so that the bridge (E03) is designed against reality, not assumptions.

## Context

career-ops is driven from an AI coding CLI via slash-command modes (`modes/*.md`), with Node scripts for PDF (Playwright), tracker merge/dedup, `npm run doctor`, a portal scanner, and config in `config/profile.yml` plus a master CV. Timebox: 2 days. Output is knowledge + fixtures, not production code.

## Acceptance criteria

- [ ] ADR-3 written, choosing which career-ops parts run in the bridge vs. as Hermes skills
- [ ] Inventory doc lists every mode, script, input file and output file with formats and example paths
- [ ] `fixtures/careerops/` contains a synthetic profile, master CV, 3 JDs, and the real outputs career-ops produced for them (evaluation report, tailored CV, PDF, tracker rows)
- [ ] Upstream commit SHA recorded
