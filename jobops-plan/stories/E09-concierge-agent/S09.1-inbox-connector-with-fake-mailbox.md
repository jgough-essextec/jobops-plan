## User story

As the Concierge, I want read access to Doc's inbox plus the ability to create drafts — and nothing more — so that I can watch for responses without any risk of sending.

## Context

Gmail API with scopes gmail.readonly + gmail.compose (drafts) + gmail.labels (to apply a 'JobOps/Seen' label); OAuth refresh token in sops. Incremental sync via historyId. IMAP fallback (read-only) for non-Gmail. Tests use a Gmail API stub and GreenMail IMAP seeded from fixtures/mailbox/*.eml. No send method exists in the client wrapper.

## Acceptance criteria

- [ ] Incremental sync processes each message once (idempotent on message id)
- [ ] Client wrapper exposes no send capability (verified by test introspection)
